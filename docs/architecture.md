# 架构与公开演示边界

## 真实项目的组成

人工设定业务范围与规则；Agent 辅助检索、阅读和整理来源；研究事实以 JSON 等结构化记录保存；通用脚本写入 Excel、校验跨表关系并维护断点；业务人员使用 Excel 筛选和反馈。

这是有人工监督、持久化记录和工具辅助的工作流。没有证据支持将它描述为独立部署的多租户 SaaS、完全无人监督 Agent 或自研基础模型。

## 公开仓库实际提供什么

| 文件 | 实际能力 |
| --- | --- |
| `demo.py` | 读取虚构 JSON，打印验收结果并返回退出码 |
| `src/research_rules.py` | 评分边界、状态、稳定 ID、显式主体键、来源引用和联系人归属规则校验 |
| `examples/synthetic_batch.json` | 四家虚构企业，覆盖 A/B/C/D 与不同研究终态 |
| `tests/test_research_rules.py` | 针对重复记录、错误等级、缺失证据和归属错误的回归测试 |

公开实现于 2026-10-07 重新整理，参考原项目的状态分离、评分和验收原则。它没有直接复制生产写表器、原始调查脚本或业务数据库。

## 必须理解的限制

- 演示输入是已整理记录；代码不执行线上搜索或模型推理。
- `entity_key` 已由上游指定，校验器只能发现同键重复，不能解决真实模糊主体消歧。
- URL 格式正确不代表页面存在，来源引用正确不代表页面支持陈述。
- `explicit_in_source` 是输入声明；代码不会独立核验网页归属。
- `all_research_terminal` 只表示本批记录满足演示规则，不代表国家覆盖饱和或生产验收通过。
- 演示要求输入带评分；不是完整候选发现阶段的数据模型。
- 生产交付为 Excel；公开演示使用 JSON，未重建原来的写表与视觉验收工具。

## 后续工程方向

在确认可公开的代码与数据范围后，再考虑可配置来源适配器、人工审阅界面和可复现模型评估。框架或服务部署的选择应服务于具体需求，不在本版本中虚构已实现能力。
